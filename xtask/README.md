# xtask

Developer commands, run as `cargo xtask <command>`. They are written in Rust rather than shell so that they work the same on every machine and in CI.

| Command | What it does |
|---|---|
| `ci` | Runs every check CI runs, in the same order: formatting, clippy, tests, the dependency rules, `cargo deny`, the REUSE lint and the offline audit. `--tests-only` builds, tests and checks the dependency rules without the lint tools. The offline audit is skipped with a notice where unprivileged user namespaces are not available (an error in CI); `--no-offline-audit` leaves it out |
| `check-deps` | Checks that each crate depends only on the workspace crates it may use, that `helikodu-testkit` is only a development dependency, that every crate outside the FFI bridges and binding crates forbids `unsafe` code, and that every crate has a README |
| `corpus` | Generates the test corpus from the recipes in `tests/corpus/` into `target/corpus/`, with a manifest of SHA-256 checksums and tool versions. Files that are up to date are kept. A recipe whose program or FFmpeg encoder is missing is skipped with a notice; `--strict` makes that an error. `--check` verifies an existing corpus against its manifest. The tag, CUE and script sets are written by `xtask` itself into files FFmpeg encodes (FLAC, Vorbis, Opus, Speex, MP3, AAC, WavPack, TTA, WMA, PCM): tags of every format byte by byte, including several values, legacy charsets, `POPM`, APEv2 and pictures, and CUE sheets in legacy charsets. Uses FFmpeg, `ffprobe` to verify each file and, where installed, `flac`, `lame`, `opusenc`, `wavpack`, `sox`, `oggenc`, `mac` and `mpcenc`. See [tests/corpus/README.md](../tests/corpus/README.md) |
| `dist` | Writes the release source tarball `target/dist/helikodu-<version>.tar.xz` (or into `--out DIR`): the files Git tracks plus untracked files that are not ignored, without build folders, with every crate of `Cargo.lock` vendored into `vendor/` and a `.cargo/config.toml` that builds from them offline. Reproducible: sorted entries, owner 0, the last commit's time (or `SOURCE_DATE_EPOCH`) as every modification time, single-threaded xz. Also writes the `.sha256` checksum and `release-notes.md`, the version's `CHANGELOG.md` section. `--tag vX.Y.Z` adds the release checks: the tag matches the workspace version, the tree is clean, and the changelog and the AppStream metainfo have entries for the version. Needs Git, GNU tar and xz. See [docs/dev/releasing.md](../docs/dev/releasing.md) |
| `offline-audit` | Runs every test program of the workspace inside a new network namespace with no interfaces (`unshare --user --net`), under a seccomp filter that kills the program with `SIGSYS` if it creates an `AF_INET` or `AF_INET6` socket; `AF_UNIX` and `AF_NETLINK` sockets keep working. A program that fails or is killed fails the audit, which names it. A self-test first proves that the harness catches Internet sockets; `--self-test` runs only that. Arguments after `--` go to every test program. The filter is installed by `helikodu-offline-launcher`, so `xtask` needs no `unsafe` code. See [tests/system/README.md](../tests/system/README.md) |
| `stress` | Runs the engine's underrun stress test (`crates/engine/tests/stress.rs`, built with optimisations): near-silent material plays in real time for `--secs N` seconds (default 60) while one busy thread per processor (`--load N`) competes for the CPU, and any underrun, error or reopened device fails it. `--backend null` (the default) uses the null sink paced like a device; `--backend pipewire` plays into a temporary PipeWire null sink that it loads and unloads with `pactl`, so nothing is ever audible. The extended checks run it for an hour |
| `synth-library` | Generates a synthetic music library for benchmarks and UI performance tests into `target/synth-library/<format>-<tracks>-seed<seed>/` (or `--out`): `--tracks N` (`100k`, `0.5m` allowed) one-second silent FLAC or Opus files (`--format flac|opus`) in an artist/album/disc folder tree, with made-up, seeded (`--seed S`) tags: Zipf-like artist popularity, compilations by "Various Artists", multi-disc albums, classical works (composer, conductor, performers, work and movement), multi-value artists and genres, dates and original dates, sort names, names in Latin with Estonian, Swedish and German letters, Cyrillic, Greek, Chinese, Japanese, Korean, Thai, Arabic and Hebrew, folder and file names in Latin-1 or cp1251 rather than UTF-8 for some albums, missing tags, and ReplayGain (FLAC) or R128 (Opus) gains on some albums. One silent template is encoded with FFmpeg (or `flac`/`opusenc`); each track is a copy of it with its own Vorbis comment block, written directly, so 100k files take seconds. `synth-library.json` holds the parameters and `tracks.jsonl` one record per track (path, percent-encoded where it is not UTF-8, as in the corpus manifest; duration; tags as key → list of values). `--names-only` writes only these two files, for tests that fill the database directly. A run with the same parameters keeps the files already there; a run with other parameters into the same folder replaces the library; a folder not made by this command is never written into. `--verify` checks up to 200 files with `ffprobe` (duration, title, album, artist) |
| `ui-checks` | Runs the UI checks of [tests/ui/](../tests/ui/README.md) under a headless compositor: builds the programs with optimisations, makes a synthetic library (`--tracks N`, default `100k`; or scans `--library DIR`) into a fresh database with `helikodu-cli scan`, then runs `perf.py` (start-up, memory, frame times, idle CPU against the performance budgets), `a11y.py` (AT-SPI audit and keyboard path) and, with `--design DIR`, `visual.py` (the designed screens under Adwaita and Breeze, light and dark, against the reference images). `--only perf|a11y|visual` picks checks; `--idle-secs N` shortens the idle phases. Reports go to `target/ui-checks/` (or `--out DIR`). Needs mutter, Python 3 with PyGObject (Atspi), Pillow and NumPy; a check whose tools are missing says it was skipped |

More commands arrive as the work needs them, such as `man` (man pages).

`xtask` never links the product crates. When it needs them, it runs Cargo or the built programs.
